# 답변 분량과 유형별 안전 대응

## 실제 확인한 기존 구조와 문제

- `api/chatkhu.js`가 OpenAI 호환 ChatKHU `/chat/completions`를 호출하고 JSON 안의 `safetyType`, `reply`를 읽었습니다. `moderation-rules.js`의 광범위한 위험 단어 탐지는 범죄·위기·단순 언급을 구분하지 않았습니다.
- 기존 `danger` 응답은 모두 같은 문구와 109·112·119를 반환했고, `index.html`에도 이 연락처가 고정되어 있었습니다.
- `app.js`는 `normal` 응답만 TTS로 연결하고, `result-player.js`가 문장별 자막과 립싱크를 처리합니다. 클라우드 음성은 `Kore` / `Iapetus`, 브라우저 대체 음성 속도는 0.95입니다. 해당 음성·자막·캐시·장면 전환 코드는 변경하지 않았습니다.

## 현재 입력 유형과 우선순위

`moderation-rules.js`의 서버 공용 `classifyInput()`으로 판단합니다. 클라이언트가 보낸 유형은 신뢰하지 않습니다.

1. **즉각적인 긴급 위험**: 현재의 멈추지 않는 출혈·호흡 곤란·의식 소실 등 구체적인 위험 신호. 적절한 긴급 연락처와 안전 행동을 안내합니다.
2. **자해 위험**: 죽고 싶다는 표현, 스스로 해치려는 의도·계획 등. 방법은 제공하지 않고 거리 두기·동행 요청·109, 이미 다쳤거나 곧 행동할 위험에는 119를 안내합니다.
3. **타해 위험**: 특정 사람을 다치게 하고 싶다는 의도·계획 등. 실행 방법 없이 대상·위험 물건과 거리 두기·주변 도움을 안내하고, 즉각적인 위협에는 112, 부상이 있으면 119를 안내합니다.
4. **불법 요청**: 타인 계정의 무단 해킹·은폐 등. 거부 이유와 개인정보 보호, 계정 복구·보안, 공식 신고·분쟁 해결 등 합법적인 대안만 제공합니다. 연락처는 **없습니다**.
5. **불명확한 안전 우려**: 위험 관련 언급은 있으나 실제 의도·긴급성이 확인되지 않은 경우. 안전 여부를 묻는 짧은 질문을 제공합니다. 연락처는 **없습니다**. 명확한 예방·교육·소설 등의 맥락을 실제 위기로 단정하지 않습니다.
6. **의료 / 법률 / 재정**: 각 전문 영역에 맞는 준비 자료와 전문가 상담을 제안하고, 진단·약 복용·소송·투자 결정을 대신 확정하지 않습니다.
7. **일반 고민**: 짧은 공감, 현실적인 분석·조언, 작은 행동 1~3개를 제공합니다.

우선순위는 번호 순이며, 전문가 영역에 앞서 **의도가 불명확한 안전 우려**를 따로 확인합니다. `투자해도`의 일부를 `자해`로 읽는 식의 단순 부분 문자열 오탐도 방지했습니다. 단, 이 분류는 규칙 기반이며 모든 표현·인용·부정·시간 관계를 완벽히 이해하는 임상 평가나 독립적인 AI 분류기는 아닙니다. 누락 가능성에 대비해 생성 프롬프트에도 자해·타해·불법 방법 제공 금지와 불확실한 안전 여부 확인 원칙을 유지합니다.

명확한 불법·위험 입력은 `lib/reply-policy.cjs`의 유형별 검토 문구를 즉시 반환해 위험한 방법을 생성할 여지를 줄입니다. 일반·전문 고민은 분류 결과와 대응 정책을 **실제 LLM 시스템 프롬프트**에 넣어 생성합니다. 모델이 이유 없는 `danger`만 반환하더라도 자동으로 긴급 연락처를 붙이지 않고 확인 질문으로 처리합니다.

## 정상 답장 분량

- 호칭·공백·줄바꿈을 포함해 **350~450자**를 목표로 합니다. 사용자가 제시한 350~500자 범위 안에서 마무리 인사를 고려해 상한을 낮췄습니다.
- 공감 1~2문장 → 상황과 현실적 제약·가능성 → 현실적인 조언 → 실행 가능한 행동 1~3개. 반복·긴 마무리를 피하고 완결된 문장으로 끝내도록 생성합니다.
- 기존 `[나이]살의 [별명]에게` 호칭과 미래의 나 페르소나를 유지합니다. TTS 재생기가 `그럼 안녕.`을 덧붙이는 방식도 유지합니다.
- 초당 공백 포함 8자 + 문단·문장 휴지 2초를 계획용 추정에 사용합니다. 이는 Gemini의 실제 속도를 측정한 값이 아닙니다. 현 작업 환경에는 API 키가 없고, 배포 URL 직접 접근도 실행 환경의 프록시에서 CONNECT 403으로 차단되어 실제 유료 생성·TTS 길이는 검증하지 않았습니다. 브라우저의 rate 0.95는 클라우드 Gemini의 속도 설정과 동일하지 않습니다.
- 목표 분량·완결성·긴급 연락처 금지 조건을 위반하면 최대 **1회** 새로 작성합니다. 두 요청은 기존 **총 50초** 제한을 공유합니다. `max_tokens: 1200`은 JSON 출력 여유를 위한 상한이며, 글자 수를 토큰 한도로 잘라 맞추지 않습니다.
- 토큰 제한으로 잘린 응답도 그대로 노출하지 않습니다. 재작성 후에도 조건을 지키지 못하면 해당 영역의 완결된 검증용 대체 편지를 반환합니다. 네트워크·인증·응답 스키마 오류는 기존 오류 처리로 연결합니다.
- 안전 안내는 빠른 전달이 중요하므로 350~450자를 채우려고 늘리지 않습니다. 기존처럼 일반 영상편지·TTS를 생성하지 않고 텍스트로 안내합니다.

## 프론트엔드와 JSON 호환

`reply`, `safetyType: 'normal' | 'danger'`, `emergencyContacts` 형식을 유지합니다. 내부 `inputType`, 분류 근거나 분석 과정은 응답에 포함하지 않습니다. `danger`는 기존 일반 영상 중단 분기이며 긴급 상황이라는 뜻으로 사용자에게 표시하지 않습니다.

`app.js`는 서버가 반환한 허용 연락처만 안전하게 DOM에 추가합니다. 빈 배열이면 연락처 영역 전체를 숨깁니다. 이전 응답의 번호도 지우므로 자해 안내를 본 뒤 해킹 요청을 해도 번호가 남지 않습니다. 제목은 분류를 드러내지 않는 “안내를 확인해 주세요”입니다.

## 로그와 검증

- `chatkhu.classified`: 내부 유형, 위험 확인 여부. 원문·이름은 기록하지 않습니다.
- `chatkhu.reply_validation`: 재작성 사유와 시도 횟수.
- `chatkhu.success`: 유형, 응답 출처(`llm`, `llm_repaired`, `validated_fallback`, `safety_policy`, `safety_clarification`), 글자 수, 정상 답장의 추정 음성 길이, 포함된 연락처.
- 실제 TTS 길이는 기존 `/api/tts`의 `tts.success.durationSeconds`로 확인할 수 있습니다.

자동 테스트: `node --test tests/*.test.cjs`

8개 입력의 오프라인 검증·보고서 재생성: `node scripts/check-chatkhu-policy.cjs`

실제 답장 생성 검증: 서버 환경에 `CHATKHU_API_KEY`, `CHATKHU_MODEL`이 안전하게 준비된 상태에서 `node scripts/check-chatkhu-policy.cjs --live`를 명시적으로 실행합니다. 이 모드는 정상·전문 고민 4건에 대해 유료 생성 요청 4회와 필요할 때만 최대 4회의 재작성 요청을 수행합니다. 안전 안내 4건은 규칙 응답이며 추가 LLM 호출이 없습니다. TTS API는 호출하지 않습니다. 키나 모델 설정이 없으면 호출 없이 종료합니다. 결과는 `docs/safety-validation-live.md`와 JSON에 기록됩니다.

[오프라인 검증 결과 및 응답 전문](safety-validation.md)은 모의 LLM 검증과 실제 규칙 응답을 명시적으로 구분합니다.
