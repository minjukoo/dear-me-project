# Dear Me

Vercel에서 Framework Preset을 `Other`로 선택하고 저장소 루트를 배포합니다.
별도의 빌드 명령이나 패키지 설치는 필요하지 않습니다. Node.js 22 이상을 사용하세요.

## 서버 환경 변수

Vercel 프로젝트의 Settings → Environment Variables에서 다음 값을 설정한 뒤 재배포하세요.

- `CHATKHU_API_KEY`: 챗쿠 API Gateway에서 발급한 키. 서버에서만 사용하며 저장소에 커밋하지 않습니다.
- `CHATKHU_MODEL`: 계정에서 사용할 수 있는 정확한 모델 ID. 제공된 명세에 모델 ID가 없어 기본값을 지정하지 않았습니다.

`POST /api/chatkhu`에 `{"message":"안녕하세요","nickname":"민민","age":25}`를 보내면 `{"reply":"..."}`를 반환합니다.
서버는 `https://factchat-cloud.mindlogic.ai/v1/gateway/chat/completions`에
Bearer 인증으로 요청합니다. 요청의 `model`, `messages`, `stream: false`와
응답의 `choices[0].message.content`는 OpenAI 호환 형식을 가정합니다.
실제 Gateway 명세가 다르면 해당 필드를 조정해야 합니다.

모델은 시스템 지시에 따라 `{"safetyType":"normal","reply":"답장"}` 또는
`{"safetyType":"danger","reply":""}` JSON을 content로 반환해야 합니다.
안전 분류가 누락되거나 형식이 잘못되면 답장을 표시하지 않고 502를 반환합니다.
서버의 보수적인 한국어·영어 위험 표현 탐지와 모델 안전 분류를 함께 사용합니다.
위험 탐지는 오탐·미탐 가능성이 있으며 전문 위험 평가를 대체하지 않습니다.
위험 응답에는 일반 편지 대신 고정 안전 안내와 109·112·119 연락처가 포함됩니다.
위험 입력과 답변은 sessionStorage에 저장하지 않습니다.

## 영상 에셋과 전송 흐름

페이지 내부 확인 모달에서 보내기를 선택하면 `/api/chatkhu` 요청과 `letter-send.mp4` 재생을 동시에 시작합니다.
일반 답장이 먼저 도착해도 전송 영상 종료/건너뛰기까지 기다립니다.
전송 영상 종료 시 응답이 대기 중이면 `lingking.mp4` 연결 영상을 재생한 뒤 회전 시계를 표시합니다.
연결 영상 중 일반 응답이 오면 영상 종료까지 기다리고, 위험·통신 오류는 즉시 해당 안내로 전환합니다.
결과 화면은 아래 캐릭터 이미지와 서버 TTS 오디오 연결을 사용합니다. 처음으로 돌아가기는 임시 답장을 지우고 사용자 설정 화면으로 돌아갑니다.
영상·이미지 에셋은 저장소 루트에서 불러옵니다. 에셋이 없으면
정적 대기 안내나 텍스트 결과를 사용합니다. 전송 영상은 기본 컨트롤 없이 화면 전체를 채웁니다. 자동 재생이 차단된 경우에만 재생 계속하기 버튼이 나타납니다.
위험 응답이 오면 영상 재생을 즉시 멈추고 별도 안전 안내 화면을 표시합니다.

Vercel 함수의 최대 실행 시간은 `vercel.json`에서 60초로 설정합니다.
외부 API 호출은 50초 후 중단하며 브라우저는 최대 65초 동안 서버 응답을 기다립니다.
오류 응답에는 진단 코드, 요청 ID와 해당하는 경우 게이트웨이 HTTP 상태가 포함됩니다.
원문 오류 본문과 API 키는 반환하거나 로그에 기록하지 않습니다.
현재 메시지 한 건만 전송하며 이전 대화 내용은 전송하지 않습니다.

Vercel의 함수 URL은 파일 확장자를 제외한 `/api/chatkhu`입니다.
JSON이 아닌 404/HTML 응답은 함수에 도달하지 못했을 가능성이 있으므로 배포의 Functions 목록에
`api/chatkhu.js`가 있는지, Root Directory가 저장소 루트인지 확인하세요.
함수 진입 시 `chatkhu.request`, 실패 시 `chatkhu.error`를 요청 ID와 함께 기록합니다.

사용자 설정은 사진 없이 별명(1~20자), 나이(1~120의 정수), 성별(여성·남성·기타·선택하지 않음)을 받습니다.
성별은 `female`, `male`, `other`, `undisclosed`로 전송하며, 누락된 기존 요청은 `undisclosed`로 처리합니다.
일반 답장은 서버에서도 `[나이]살의 [별명]에게`로 시작하도록 보장합니다.
안전 안내에는 편지 호칭을 붙이지 않습니다.

오프닝 종료·건너뛰기 후에는 `start.png` 배경과 시작 버튼을 표시하며, 버튼을 눌러 사용자 설정으로 이동합니다.
설정·편지 작성 화면은 `background.png`를 전체 배경으로 사용합니다. 두 PNG는 저장소 루트에 포함됩니다.

`letter-send.mp4`는 전달받은 약 10초짜리 H.264/AAC 영상을 포함합니다. 재인코딩 없이 fast-start로 정리했으며, 전송 확인 직후 원본 음성이 있는 인라인 자동재생과 API 요청을 동시에 시작합니다.
로딩은 영상 대신 제공된 `loading_bg.png`와 투명 PNG `loading_needle.png`를 사용합니다.
둘 다 1672×941 캔버스이며 분침의 원본 축 (832,487)을 배경 축 (828,491)에 맞춰 배치합니다.
변환 중심은 분침 캔버스의 (49.760766%,51.753454%)이고 위치를 (-4,+4)px만큼 캔버스 비율로 보정합니다.
분침은 8초에 한 번 시계 방향으로 회전하며 로딩 화면이 활성일 때만 움직입니다.
동작 줄이기 설정에서는 회전 없이 대기 문구를 표시합니다.
PC·가로 화면은 배경을 꽉 채우고, 모바일 세로는 두 이미지를 동일한 비율로 중앙에 배치합니다.

## 말하는 결과 편지

전달받은 다음 9개 PNG 에셋을 저장소 루트에 포함합니다. 대소문자와 확장자를 그대로 유지합니다.

- `background_room.png`
- `male_normal.png`, `male_mouth.png`, `male_smile.png`, `male_hello.png`
- `female_normal.png`, `female_mouth.png`, `female_smile.png`, `female_hello.png`

이미지는 방 배경이 포함된 전체 프레임입니다. 누락된 프레임은 기본 이미지 또는 안내 문구로 대체합니다.
남성·여성 설정은 전체 화면 캐릭터 편지로 바로 이어집니다. 기타·선택하지 않음은 별도 캐릭터 선택 화면에서 다음으로를 누른 뒤 재생합니다.
`result-player.js`가 서버 TTS의 WAV를 재생하고 기존 문장별 자막 칸과
250ms 간격으로 normal/mouth 이미지를 교체합니다. 정밀 음소 립싱크가 아닌 입 모양 토글 연출입니다.
서버 TTS 규격과 실제 음성 검증 범위는 TTS.md를 확인하세요.
기본 재생 버튼 없이 음성을 자동으로 시작합니다. 브라우저의 음성 자동재생 정책은 기기에 따라 다릅니다.
서버 음성 생성·준비가 실패하거나 30초를 초과하면 기기의 기본 한국어 음성으로 자동 전환합니다. 화면 이탈 시 음성과 타이머를 중단합니다.
동작 줄이기 설정에서는 입 모양 반복을 생략합니다.
캐릭터가 본문을 마치면 손 든 `hello` 이미지를 고정하고 "그럼 안녕."을 읽습니다.
인사 음성 종료 후에도 2.8초 동안 같은 포즈를 유지한 뒤 `background_room.png` 빈방으로 전환합니다.
레거시 브라우저 음성 경로도 코드에 보존합니다. 건너뛰기는 인사·대기 타이머도 취소합니다.
빈방에는 다시 재생하기와 편지 받기만 표시합니다. 편지 받기를 누르면 `background.png` 배경의 텍스트 답장과 저장 기능을 이용할 수 있습니다.
편지지 다운로드는 `background.png`를 data URL로 내장한 `dear-me-letter.html` 파일입니다.
오프라인에서도 배경과 텍스트를 표시하며 브라우저 인쇄/PDF 저장이 가능합니다.
원문 텍스트는 `dear-me-letter.txt`로도 저장할 수 있습니다.

## 화면 비율과 전체화면

오프닝은 자동재생하지 않고 정지 상태로 준비합니다. 화면 전체를 덮는 시작 영역을 클릭·터치하거나
키보드로 활성화하면 같은 사용자 동작 안에서 문서 전체 Fullscreen API 요청과 오프닝 재생을 함께 시작합니다.
전체화면 거절·미지원 시에도 영상은 일반 화면으로 재생합니다. ESC로 해제한 경우 시작하기 버튼이 전체화면을 다시 강제하지 않습니다.
ESC 또는 오른쪽 위 전체화면 나가기 버튼으로 해제하며 변경 이벤트로 버튼 상태를 맞춥니다.
모바일/터치 기기는 전체화면 진입 후 `screen.orientation.lock('landscape')`를 시도합니다.
지원되지 않거나 거절되면 세로 화면을 유지하고 회전 안내를 표시합니다. 해제 시 방향 잠금도 풉니다.
문서 전체화면 자체가 미지원인 기기는 일반 화면으로 계속합니다.

PC·가로 화면의 오프닝·전송·캐릭터는 여백 없이 채우고 가장자리 잘림을 허용합니다.
1024px 이하 세로 화면에서는 중앙에 16:9 프레임을 유지하며 남는 위아래를 배경으로 채웁니다.
모바일 전용 이미지는 아직 받지 않았습니다. 현재 `--mobile-cinema-background`의 기존 `background.png`를 사용하며,
새 에셋을 받으면 이 변수의 URL만 교체합니다.
`media-layout.js`는 이미지와 자막에 동일한 16:9 좌표를 적용합니다. 제공된 이미지의 자막 바에
실제 자막을 겹치며, 극단적인 화면 비율에서 자막만 화면 안으로 보정합니다.
원본은 변경하지 않습니다. 이미지 로딩·입 모양·문장 길이에 따라 프레임 크기가 변하지 않으며
시네마 화면의 진입 애니메이션도 제거했습니다.

전송 확인은 `window.confirm()` 대신 문서 내부 `<dialog>` 모달을 사용합니다.
배경 입력을 잠그고 취소에 초기 포커스를 두며, 취소·ESC 시 API를 호출하지 않습니다.
보내기를 선택한 경우에만 기존 전송 흐름을 시작하며 확인창 때문에 전체화면을 종료하지 않습니다.

## 새로고침과 영상 편지 건너뛰기

사용자 조작 이후 새로고침·페이지 이탈 시 `beforeunload`로 브라우저 확인창을 요청합니다.
안내 문구는 브라우저가 결정하며, 특히 모바일에서는 표시가 생략될 수 있습니다.
취소하면 현재 내용과 임시 저장을 유지합니다. 새로고침을 진행하면 새 페이지에서
해당 답장의 sessionStorage와 입력값을 지우고 정지된 오프닝부터 다시 시작합니다.
캐릭터 화면 왼쪽 위 건너뛰고 편지 받기는 음성과 타이머를 중단하고 텍스트·다운로드 화면으로 바로 이동합니다.

## 로딩 이미지 준비와 연결 영상

`lingking.mp4`는 제공된 약 5초짜리 연결 영상이며 fast-start로 정리했습니다.
연결 영상은 초기부터 미리 읽고, 준비된 프레임이 재생될 때 전송 영상에서 전환합니다.
`loading_bg.png`는 실제 이미지 요소로 미리 읽어 decode를 완료한 뒤에만 분침을 노출합니다.
연결 영상이 끝나도 배경이 준비되지 않았으면 마지막 프레임을 유지합니다.
배경이 준비되면 영상 위에서 0.45초 동안 투명도를 줄여 동일 구도의 회전 시계를 드러냅니다.
배경 로딩 실패 시 바늘을 숨긴 채 마지막 프레임과 대기 안내를 유지하며, 응답이 오면 계속 진행합니다.

전송 영상의 전체화면 버튼은 opening 테마, 연결 영상·시계 대기 화면은 glass 테마를 사용합니다.
텍스트 편지 화면과 다운로드 HTML 편지지는 로고 없는 `background.png` 배경을 사용합니다.

## 서버 음성(TTS)

ChatKHU Gemini TTS 연결은 [TTS.md](TTS.md)에 환경 변수, 응답 규격 가정, 재사용·재시도,
검증 명령과 실제 호출 미검증 범위를 정리했습니다. 기존 영상·시계·캐릭터 연출은 유지합니다.

## 영상 소리와 BGM

`sound-manager.js`는 첫 화면 클릭에서 TTS와 같은 native Audio 요소를 준비하고 영상 원본 소리를 켭니다.
영상 재생 요청은 전체화면 요청보다 먼저 호출하여 사용자 동작 권한을 활용합니다.
`website_bgm.mp3`와 `letter_bgm.mp3`는 전달받은 원본 파일 그대로 포함합니다.

- 오프닝·편지 전송·연결 영상: 원본 소리, 볼륨 100%, BGM 중단.
- 편지 작성·전송 확인 모달: letter BGM 반복, 볼륨 42%.
- 시작·설정·캐릭터 선택·시계 대기·빈방·텍스트 편지: website BGM 반복, 볼륨 45%.
- 캐릭터 TTS 화면·안전 안내: BGM 중단.

음악은 처음 사용자 클릭 이후에만 재생하며 하나의 지속적인 native Audio 요소와 브라우저 파일 캐시를 사용합니다.
같은 BGM의 화면끼리 이동하면 곡을 처음부터 다시 시작하지 않습니다.
브라우저가 영상 소리 재생을 차단하면 새 소리 버튼 없이 해당 영상을 무음으로 계속합니다.
기존 영상 복구 버튼은 유지하지만 소리 전용 버튼은 새로 만들지 않습니다.
BGM 실패는 화면 진행을 막지 않으며, 숨겨진 탭과 페이지 이탈 시 BGM을 중단합니다.
TTS 엔드포인트와 캐릭터 립싱크·이미지·영상 상태 분기는 그대로 유지합니다.

소리 진단이 필요하면 브라우저 콘솔에서 `DearMeSound.getState()`로 BGM 소스·재생·볼륨·오류 메타데이터를 확인할 수 있습니다. 키나 편지 내용은 포함하지 않습니다.

## 카카오톡 공유 미리보기

HTML head의 Open Graph/Twitter 메타데이터에서 공유 제목·소개와 `start.png` 로고 이미지를 지정합니다.
정적 HTML에 선언하므로 카카오 크롤러가 JavaScript를 실행할 필요가 없습니다.
배포 후에도 기존 카드가 남으면 카카오 공유 디버거/OG 캐시 초기화 도구에서
`https://dear-me-project.vercel.app/` 캐시를 갱신해야 할 수 있습니다.
